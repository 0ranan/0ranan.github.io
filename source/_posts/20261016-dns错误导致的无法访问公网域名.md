# dns错误导致的无法访问公网域名

## 初步确诊

curl 的时候提示无法解析服务

```bash
[root@localhost ~]# ping www.baidu.com
ping: www.baidu.com: Name or service not known
[root@localhost ~]# curl www.baidu.com
curl: (6) Could not resolve host: www.baidu.com
```

能够ping通公共dns

```bash
[root@localhost ~]# ping 8.8.8.8 -c 4
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=107 time=53.1 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=107 time=52.1 ms
64 bytes from 8.8.8.8: icmp_seq=3 ttl=107 time=46.1 ms
64 bytes from 8.8.8.8: icmp_seq=4 ttl=107 time=45.9 ms

--- 8.8.8.8 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3002ms
rtt min/avg/max/mdev = 45.903/49.313/53.103/3.311 ms
```

## 确证DNS解析失败

1. 先检查本台设备的 DNS。

```bash
[root@localhost ~]# cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 10.100.6.10
nameserver 10.100.6.11
```

两台都是内网 10.100.6.x 段的地址，跟刚才 ping 得通的 8.8.8.8 不在一个网段。

2. 用系统默认的这两台 DNS 解析域名。

```bash
[root@localhost ~]# nslookup baidu.com
;; connection timed out; no servers could be reached
```

DNS查询超时

3. 指定 8.8.8.8 公共 DNS 再次尝试解析。

```bash
[root@localhost ~]# nslookup baidu.com 8.8.8.8
Server:         8.8.8.8
Address:        8.8.8.8#53

Non-authoritative answer:
Name:   baidu.com
Address: 124.237.177.164
Name:   baidu.com
Address: 111.63.65.103
Name:   baidu.com
Address: 111.63.65.247
Name:   baidu.com
Address: 110.242.74.102

[root@localhost ~]# curl 124.237.177.164
<a href="https://www.baidu.com/">Moved Permanently</a>.
```

经过测试dns可以正常被解析，直接通过解析出来的ip地址进行访问测试通过，说明机器到公网是好的。

4. 看程序自己实际走的那条解析路径。

```bash
[root@localhost ~]# getent hosts baidu.com
[root@localhost ~]#
```

getent 一行输出都没有，跟前面 curl、ping 的报错对得上——系统解析库用的还是那两个内网 DNS。

## 解决方案

有两种解题思路：

1. 使用内网DNS
2. 换掉本地DNS

### 解决方案1：修复内网DNS（失败）

```bash
[root@localhost ~]# nc -vz 10.100.6.10 53
Ncat: Version 7.92 ( https://nmap.org/ncat )
Ncat: TIMEOUT.
[root@localhost ~]# ping -c 4 10.100.6.10
PING 10.100.6.10 (10.100.6.10) 56(84) bytes of data.

--- 10.100.6.10 ping statistics ---
4 packets transmitted, 0 received, 100% packet loss, time 3049ms

[root@localhost ~]# ping -c 4 10.100.6.11
PING 10.100.6.11 (10.100.6.11) 56(84) bytes of data.

--- 10.100.6.11 ping statistics ---
4 packets transmitted, 0 received, 100% packet loss, time 3051ms
```

连ip都不通，直接放弃。

### 解决方案2：换掉DNS（）

1. 检查当前文件目录配置文件

```bash
[root@localhost ~]# ls /etc/sysconfig/network-scripts/
ifcfg-enp3s0
[root@localhost ~]# cat /etc/sysconfig/network-scripts/ifcfg-enp3s0
TYPE=Ethernet
PROXY_METHOD=none
BROWSER_ONLY=no
BOOTPROTO=dhcp
DEFROUTE=yes
IPV4_FAILURE_FATAL=no
IPV6INIT=yes
IPV6_AUTOCONF=yes
IPV6_DEFROUTE=yes
IPV6_FAILURE_FATAL=no
IPV6_ADDR_GEN_MODE=stable-privacy
NAME=enp3s0
UUID=aa897f0a-f373-4615-8186-f695a6d9557c
DEVICE=enp3s0
ONBOOT=yes
```

| 配置行 | 含义 | 从这里能看出什么 |
|---|---|---|
| `TYPE=Ethernet` | 连接类型是以太网 | 这是有线以太网，不是 Wi-Fi、桥接、bond 等 |
| `PROXY_METHOD=none` | 不使用代理 | 这个连接不配置代理 |
| `BROWSER_ONLY=no` | 代理设置不限于浏览器 | 但前面是 `none`，所以基本无影响 |
| `BOOTPROTO=dhcp` | IPv4 地址通过 DHCP 自动获取 | 没有静态 IP，IP、掩码、网关、DNS 大概率都来自 DHCP |
| `DEFROUTE=yes` | 把这个连接作为默认路由 | 默认流量从 `enp3s0` 出去，所以它能上公网 |
| `IPV4_FAILURE_FATAL=no` | IPv4 配置失败时，不认为整个连接致命失败 | IPv4 出问题不一定导致连接整体 down |
| `IPV6INIT=yes` | 启用 IPv6 | 这个连接会初始化 IPv6 |
| `IPV6_AUTOCONF=yes` | IPv6 自动配置 | 通过路由器公告等自动获取 IPv6 地址 |
| `IPV6_DEFROUTE=yes` | 允许 IPv6 默认路由 | 如果 IPv6 可用，可以走 IPv6 默认路由 |
| `IPV6_FAILURE_FATAL=no` | IPv6 失败不影响整体连接 | IPv6 不通不会让整个连接失败 |
| `IPV6_ADDR_GEN_MODE=stable-privacy` | IPv6 地址生成模式为稳定隐私模式 | 生成的 IPv6 地址相对稳定，但带隐私保护 |
| `NAME=enp3s0` | NetworkManager 里的连接名 | 用 `nmcli connection modify` 时，连接名就是 `enp3s0` |
| `UUID=aa897f0a-f373-4615-8186-f695a6d9557c` | 连接的唯一标识 | 和 `nmcli connection show` 里看到的 UUID 对应 |
| `DEVICE=enp3s0` | 绑定的物理网卡 | 这个配置作用于 `enp3s0` 这块网卡 |
| `ONBOOT=yes` | 开机自动启用 | 系统启动时会自动激活这个连接 |

2. 检查 NetworkManager 服务连接对象

```bash 
[root@localhost ~]# nmcli connection show
NAME    UUID                                  TYPE      DEVICE
enp3s0  aa897f0a-f373-4615-8186-f695a6d9557c  ethernet  enp3s0
virbr0  679439fa-f9ed-400e-b7cc-dd9ce11a47cb  bridge    virbr0
```


### 尝试重新连接，试图刷新dhcp

```bash
nmcli connection down enp3s0 && nmcli connection up enp3s0
```

### 使用nmcli强制指定有效DNS

```bash
# 查看当前网卡
[root@localhost etc]# nmcli connection show
NAME    UUID                                  TYPE      DEVICE
enp3s0  aa897f0a-f373-4615-8186-f695a6d9557c  ethernet  enp3s0
virbr0  21f657d8-95ef-4227-bb0b-e0e555bc59a5  bridge    virbr0

# 检查当前网卡的详细信息
[root@localhost ~]# nmcli device show  enp3s0

[root@localhost etc]# nmcli con mod enp3s0 ipv4.dns "10.100.6.10 10.100.6.11 223.5.5.5"

[root@localhost etc]# nmcli con mod enp3s0 ipv4.ignore-auto-dns yes

[root@localhost etc]# nmcli con up enp3s0
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/5)

```
