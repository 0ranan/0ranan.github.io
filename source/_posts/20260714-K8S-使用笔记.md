# K8S-使用笔记

## 常用K8S版本

| 特性维度 | k3d | kind | minikube | k3s | k0s | MicroK8s |
| --- | --- | --- | --- | --- | --- | --- |
| 本质与定位 | k3s 的 Docker 封装器，在 Docker 中运行 k3s | 标准 K8s 在 Docker 中运行的测试工具 | 本地开发专用的单节点集群工具 | 轻量级 K8s 发行版，CNCF 认证 | 零摩擦的单二进制 K8s 发行版 | Ubuntu 生态的轻量级发行版 |
| 底层实现 | Docker 容器作为节点，运行 k3s | Docker 容器作为节点，运行标准 K8s 组件 | 通常在 VM 中运行单节点集群；也支持 Docker 模式 | 单一二进制文件，所有组件打包为一个进程 | 单一二进制文件，包含所有 K8s 组件 | Snap 包形式安装，支持多节点 |

## 配置管理工具

两者都是 K8S 应用部署与配置管理工具，核心区别在于思路不同：

- **Helm**：K8S 的包管理器。将应用打包为 Chart（模板 + 默认值），通过 `helm install` 一键部署，支持版本管理、回滚和仓库分发，适合需要复用和分发的通用应用。
- **Kustomize**：原生的配置叠加工具（`kubectl apply -k`）。不引入模板语法，而是通过 Overlay 机制对基础 YAML 做 patch，适合追求纯 YAML、不想引入额外工具链的场景。

> 简单选择：需要模板化和版本管理 → Helm；需要轻量、纯 YAML 的环境差异管理 → Kustomize。

## 工具介绍

### Kind

- **定位**：一个用于在 Docker 容器内运行 Kubernetes 集群的工具。
- **功能**：它通过容器来模拟 Kubernetes 节点，从而在本地环境中快速创建和销毁符合规范的 Kubernetes 集群。
- **主要应用场景**：本地开发环境搭建和持续集成（CI）流程中的自动化测试。

### Kubectl

- **定位**：Kubernetes 集群的命令行控制接口。
- **功能**：它通过调用 Kubernetes API 服务器，对集群内的各类资源（如 Pod、Service、Deployment 等）执行创建、查询、修改和删除等操作。
- **主要应用场景**：作为管理员和开发者与集群交互的主要工具，用于应用部署、状态监控和故障排查。

### Helm

- **定位**：Kubernetes 应用的包管理工具。
- **功能**：它将一组相关的 Kubernetes 资源定义文件打包为一个称为"Chart"的软件包，并支持通过模板化配置来管理不同环境下的部署。Helm 提供了应用实例的安装、升级、回滚和版本管理功能。
- **主要应用场景**：将复杂的多服务应用标准化打包，简化在 Kubernetes 集群上的部署和运维流程。

### 工作关系

1. **Kind** 负责提供底层的 Kubernetes 运行环境。
2. **Kubectl** 负责与这个环境进行交互，执行单次性的资源操作。
3. **Helm** 作为一个更高级的自动化工具，利用 Kubectl（或直接调用 API）的机制，以软件包的形式管理和部署复杂的应用。

## kubectl 命令

按 **集群 → 命名空间 → Pod** 的概念层级整理。

### 集群层级

#### 集群信息

| 命令 | 说明 |
| --- | --- |
| `kubectl version` | 查看客户端和服务端版本 |
| `kubectl cluster-info` | 查看核心服务地址（API Server、Dashboard 等） |

#### 节点管理

| 命令 | 说明 |
| --- | --- |
| `kubectl get nodes` | 查看所有节点状态、年龄、版本 |
| `kubectl get nodes -o wide` | 查看节点详情（IP、内核版本等） |
| `kubectl describe node <节点>` | 查看节点详细信息和事件 |
| `kubectl top nodes` | 查看节点资源使用率（需 Metrics Server） |

#### 节点维护

| 命令 | 说明 |
| --- | --- |
| `kubectl cordon <节点>` | 标记节点为不可调度（原 Pod 不受影响） |
| `kubectl drain <节点> --ignore-daemonsets --delete-emptydir-data` | 安全驱逐节点上所有 Pod，用于维护前 |
| `kubectl uncordon <节点>` | 取消不可调度标记，恢复调度 |

#### 配置与上下文

| 命令 | 说明 |
| --- | --- |
| `kubectl config current-context` | 查看当前连接的集群 |
| `kubectl config get-contexts` | 查看所有已配置的集群 |
| `kubectl config use-context <上下文>` | 切换集群 |
| `kubectl config set-context --current --namespace=<ns>` | 设置默认命名空间 |

### 命名空间层级

| 命令 | 说明 |
| --- | --- |
| `kubectl get ns` | 列出所有命名空间 |
| `kubectl describe ns <命名空间>` | 查看命名空间详情 |
| `kubectl create ns <命名空间>` | 创建命名空间 |
| `kubectl delete ns <命名空间>` | 删除命名空间（会删除该命名空间下所有资源） |
| `kubectl get pods -n <命名空间>` | 临时指定命名空间执行命令 |

### Pod 层级

#### 查看与创建

| 命令 | 说明 |
| --- | --- |
| `kubectl get pods` | 列出当前命名空间下的 Pod |
| `kubectl get pods -A` | 列出所有命名空间下的 Pod |
| `kubectl get pods -o wide` | 查看 Pod 详情（IP、所在节点等） |
| `kubectl describe pod <Pod>` | 查看 Pod 详细配置和事件（排错最常用） |
| `kubectl run <Pod> --image=<镜像>` | 快速启动一个 Pod（测试用） |
| `kubectl apply -f <文件.yaml>` | 根据 YAML 文件创建/更新资源 |
| `kubectl delete pod <Pod>` | 删除 Pod |

#### 日志与交互

| 命令 | 说明 |
| --- | --- |
| `kubectl logs <Pod>` | 查看 Pod 标准输出日志 |
| `kubectl logs -f <Pod>` | 实时追踪日志 |
| `kubectl logs -f <Pod> -c <容器>` | 查看指定容器的日志（多容器 Pod） |
| `kubectl exec -it <Pod> -- /bin/bash` | 进入 Pod 终端（无 bash 则用 `/bin/sh`） |

#### 调试与工具

| 命令 | 说明 |
| --- | --- |
| `kubectl top pod <Pod>` | 查看 Pod 资源使用率（需 Metrics Server） |
| `kubectl port-forward <Pod> <本地端口>:<Pod端口>` | 端口转发，本地访问集群内服务 |
| `kubectl cp <本地路径> <Pod>:<容器内路径>` | 复制文件到 Pod |
| `kubectl cp <Pod>:<容器内路径> <本地路径>` | 从 Pod 复制文件到本地 |
| `kubectl get pod <Pod> -o yaml` | 查看资源的 YAML 配置模板 |

### 常用简写

| 全称 | 简写 | 示例 |
| --- | --- | --- |
| namespace | ns | `kubectl get ns` |
| pods | po | `kubectl get po -A` |
| services | svc | `kubectl get svc` |
| deployments | deploy | `kubectl get deploy` |

> 忘记参数时，随时在命令后加 `--help`。
