# SSH-反向隧道打通无公网-NAT-主机

A 是 openEuler，没有公网 IP，只有出站；B 是 Ubuntu，有公网 IP。要从外面 SSH 进 A 的 22，只能借 B 的端口：让 A 主动连 B，把 A 的 22 挂到 B 的 4022 上。

A 上先手敲：

```bash
ssh -N -R 0.0.0.0:4022:127.0.0.1:22 root@B的IP
```

B 上看监听，`Local Address` 是 `127.0.0.1:4022`，外部连不进来。反向转发的监听 socket 由 B 的 sshd 替客户端建，默认只绑环回，客户端写不写 `0.0.0.0` 都一样。要绑全网卡，B 的 sshd 得放行客户端指定地址：

```bash
# 允许 ssh 客户端在发起反向转发时自己指定要绑定的地址
sudo tee /etc/ssh/sshd_config.d/90-reverse-tunnel.conf >/dev/null <<'EOF'
GatewayPorts clientspecified
EOF
# 语法检查 和 刷新配置文件
sudo sshd -t && sudo systemctl reload ssh
```

Ubuntu 的服务名是 `ssh` 不是 `sshd`；云镜像常把配置拆进 `/etc/ssh/sshd_config.d/*.conf`，改主文件会被盖过，所以写成 drop-in。Ubuntu 的端口限制走 AppArmor，不拦这个。换到开 SELinux 的发行版做跳板，sshd 绑 4022 会被 AVC 拒：

```bash
sudo semanage port -a -t ssh_port_t -p tcp 4022
```

改完 `Local Address` 变成 `0.0.0.0:4022`，外部 `ssh -p 4022 root@B的IP` 能登进 A。手敲的隧道断一次就没了，交给 systemd 托管。

## 建专用账号

隧道不跟平时运维共用密钥：

```bash
sudo useradd -r -m -d /var/lib/tunnel -s /usr/sbin/nologin tunnel
sudo mkdir -p /var/lib/tunnel/.ssh && sudo chmod 700 /var/lib/tunnel/.ssh
sudo ssh-keygen -t ed25519 -N "" -f /var/lib/tunnel/.ssh/id_tunnel
sudo chown -R tunnel:tunnel /var/lib/tunnel
```

私钥不设口令，开机自启时没有终端输密码，安全性靠 B 侧那把锁兜。

## B 侧的跳板账号

```bash
sudo useradd -m -s /bin/bash tunnel
sudo mkdir -p /home/tunnel/.ssh && sudo chmod 700 /home/tunnel/.ssh
sudo touch /home/tunnel/.ssh/authorized_keys
sudo chmod 600 /home/tunnel/.ssh/authorized_keys
sudo chown -R tunnel:tunnel /home/tunnel/.ssh
```

把 A 的公钥追加进 B 的 `authorized_keys`，前面带一串限制：

```text
permitlisten="0.0.0.0:4022",no-pty,no-X11-forwarding,no-agent-forwarding,no-user-rc ssh-ed25519 AAAA...A上的公钥
```

`restrict` 不要写，它含 `no-port-forwarding`，反向转发会被一起禁掉。真正卡住「这把钥匙只能在 4022 上监听」的是 `permitlisten`；不写它，A 一旦被拿下，这把钥匙就能在 B 上开任意端口。多个端口写成列表：`permitlisten="0.0.0.0:4022,0.0.0.0:4023"`。

sshd 侧再给这个账号收一层，写进 `/etc/ssh/sshd_config.d/91-tunnel-match.conf`：

```text
Match User tunnel
    AllowTcpForwarding remote
    PermitOpen none
    PermitTTY no
    X11Forwarding no
    AllowAgentForwarding no
```

```bash
sudo sshd -t && sudo systemctl reload ssh
```

## A 侧客户端配置

B 的 host key 先手工录入，别让它首次自动信任：

```bash
# B 上取指纹，另找一条可信通道核对
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

# A 上写入
sudo ssh-keyscan -t ed25519 B的IP | sudo tee /var/lib/tunnel/.ssh/known_hosts
sudo chown tunnel:tunnel /var/lib/tunnel/.ssh/known_hosts
sudo chmod 600 /var/lib/tunnel/.ssh/known_hosts
```

`/var/lib/tunnel/.ssh/config` 写成一个 Host 段，比在 `ExecStart` 里堆一长串 `-o` 干净：

```text
Host tunnel-to-b
    HostName B的IP
    Port 22
    User tunnel
    IdentityFile /var/lib/tunnel/.ssh/id_tunnel
    IdentitiesOnly yes

    RemoteForward 0.0.0.0:4022 127.0.0.1:22

    ExitOnForwardFailure yes
    ServerAliveInterval 15
    ServerAliveCountMax 3
    TCPKeepAlive yes
    StrictHostKeyChecking yes
    UserKnownHostsFile /var/lib/tunnel/.ssh/known_hosts
```

`ExitOnForwardFailure yes`：B 上 4022 被占时，ssh 照样连得上，只是转发是废的，一切看着正常却不通；加上它，绑不上就直接退出，systemd 才看得见。`ServerAliveInterval 15` 加 `ServerAliveCountMax 3`：45 秒没响应就判定链路死了，ssh 退出后由 systemd 拉起。

```bash
sudo chown tunnel:tunnel /var/lib/tunnel/.ssh/config
sudo chmod 600 /var/lib/tunnel/.ssh/config
```

## systemd 单元

`/etc/systemd/system/ssh-tunnel.service`：

```ini
[Unit]
Description=SSH reverse tunnel A -> B
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=tunnel
Group=tunnel

ExecStart=/usr/bin/ssh -N -F /var/lib/tunnel/.ssh/config tunnel-to-b

Restart=always
RestartSec=10

NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=read-only
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
RestrictSUIDSGID=yes
RestrictRealtime=yes
LockPersonality=yes
MemoryDenyWriteExecute=yes
CapabilityBoundingSet=
AmbientCapabilities=
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX

[Install]
WantedBy=multi-user.target
```

`ExecStart` 直接用系统自带的 ssh，不带监控进程。转发失败或被 `ServerAlive` 判死时 ssh 自己退出，`Restart=always` 十秒后把进程拉回来。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ssh-tunnel
```

## 放行端口

B 上：

```bash
sudo ufw allow from <自己的固定出口IP> to any port 4022 proto tcp
```

B 是云主机的话，控制台的入站安全组也要开 4022，同样只放固定源地址。系统防火墙开了、安全组没开，等于没开。

4022 对外开的就是 A 的 sshd。A 上把密码登录关掉、只留密钥，`PermitRootLogin no`，不然迟早被扫爆。经隧道进来的连接，在 A 上看来源地址都是 `127.0.0.1`，按来源 IP 做的白名单和 fail2ban 在这个场景里会失效。

## 收尾验证

A 上：

```bash
systemctl status ssh-tunnel
```

`Active: active (running)`。

B 上：

```bash
sudo ss -tlnp | grep 4022
```

`Local Address` 是 `0.0.0.0:4022`，进程是 sshd。

外部任意机器：

```bash
ssh -p 4022 root@B的IP
```

登进去之后 `hostname` 出来的是 A。

断线自愈再真试一次。B 上 `sudo systemctl restart ssh`，A 上 `journalctl -u ssh-tunnel -f` 里出现断开后重新连上，B 上 `ss` 里 4022 重新出现。
