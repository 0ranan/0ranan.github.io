# Spec Kit 使用指南

## 核心四阶段工作流

Spec Kit 的核心在于其结构化的四步工作流。你可以在 AI 代理的对话框中使用对应的斜杠命令来推进开发：

### 阶段 1：Specify（规格化）

**命令**：`/speckit.specify` 或 `/specify`

**目标**：明确你要构建什么以及为什么。专注于业务逻辑、用户旅程和成功标准，而不是具体的技术栈。AI 会生成一份详细的规格文档（如 spec.md），你需要审查其业务逻辑和边界条件是否准确。

### 阶段 2：Plan（规划）

**命令**：`/speckit.plan` 或 `/plan`

**目标**：制定技术实现计划。你需要提供技术栈选型（如 Node.js + MongoDB），AI 会据此生成包含架构设计、数据库模型和 API 规划的技术文档（如 plan.md）。

### 阶段 3：Tasks（任务分解）

**命令**：`/speckit.tasks` 或 `/tasks`

**目标**：将规格和计划拆解为可执行的待办事项列表（如 tasks.md）。你需要对生成的任务进行优先级排序和依赖关系确认。

### 阶段 4：Implement（实现）

**命令**：`/speckit.implement`

**目标**：基于 TDD（测试驱动开发）原则生成代码。AI 会强制先生成测试用例，测试通过后再实现具体功能代码。

## ⚡ 快速开始

### 1. 安装 Specify CLI

需要 **[uv](https://docs.astral.sh/uv/)**（[安装 uv](./docs/install/uv.md)）。将 `vX.Y.Z` 替换为 [spec-kit releases](https://github.com/github/spec-kit/releases) 中的最新标签：

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@vX.Y.Z
```

有关替代安装方式、验证、升级和故障排除，请参阅[安装指南](./docs/installation.md)。

### 2. 初始化项目

```bash
specify init my-project --integration copilot
cd my-project
```

要检查更新或升级已安装的 CLI，请使用自管理命令。有关详细场景和自定义选项，请参阅[升级指南](./docs/upgrade.md)。

```bash
# 检查是否有更新的版本可用（只读——不会修改任何内容）
specify self check

# 预览将要运行的内容，而不实际升级
specify self upgrade --dry-run

# 就地升级到最新的稳定版本（自动检测 uv tool 或 pipx 安装）
specify self upgrade

# 或固定到特定的发布标签（将 vX.Y.Z[suffix] 替换为你想要的发布标签）
specify self upgrade --tag vX.Y.Z[suffix]
```

直接运行 `specify self upgrade` 会立即执行，与 `pip install -U` 和 `npm update` 等命令的无提示行为一致。对于 `uv tool` 安装，它会在底层运行 `uv tool install specify-cli --force --from <git ref>`，因此固定的发布标签可以正常工作，包括 dev、alpha/beta/rc 或构建元数据后缀。`uvx`（临时）运行和源码检出会被检测到，并生成针对特定路径的指导而非运行安装程序。设置 `SPECIFY_UPGRADE_TIMEOUT_SECS` 可以限制安装子进程的运行时间（默认：无超时——如需要可使用 `Ctrl+C` 中断）。

### 3. 建立项目原则

在项目目录中启动你的编码代理。大多数代理通过 `/speckit.*` 斜杠命令暴露 spec-kit；Codex CLI 在技能模式下使用 `$speckit-*`；GitHub Copilot CLI 使用 `/agents` 来选择代理或在提示中直接寻址。

使用 **`/speckit.constitution`** 命令创建项目的基本原则和开发指南，这些将指导所有后续的开发工作。

```bash
/speckit.constitution 创建关注代码质量、测试标准、用户体验一致性和性能要求的原则
```

### 4. 创建规格

使用 **`/speckit.specify`** 命令描述你想要构建的内容。关注**做什么**和**为什么做**，而不是技术栈。

```bash
/speckit.specify 构建一个可以帮助我整理照片到不同相册的应用程序。相册按日期分组，可以在主页面上通过拖放重新组织。相册之间不存在嵌套关系。在每个相册内，照片以瓦片式界面预览。
```

### 5. 创建技术实施计划

使用 **`/speckit.plan`** 命令提供你的技术栈和架构选择。

```bash
/speckit.plan 应用程序使用 Vite，尽量减少库的数量。尽可能使用原生 HTML、CSS 和 JavaScript。图片不上传到任何地方，元数据存储在本地 SQLite 数据库中。
```

### 6. 拆分为任务

使用 **`/speckit.tasks`** 从实施计划创建可执行的任务列表。

```bash
/speckit.tasks
```

### 7. 执行实现

使用 **`/speckit.implement`** 执行所有任务，按照计划构建你的功能。

```bash
/speckit.implement
```

有关详细的分步说明，请参阅我们的[综合指南](./spec-driven.md)。
