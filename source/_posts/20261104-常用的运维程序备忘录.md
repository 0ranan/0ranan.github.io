## 网络工具

### nc
全称 netcat，Linux 里的“网络瑞士军刀”，TCP/UDP 的读写都能干。

发行版里有两套实现：OpenBSD 版（包名 `netcat-openbsd`，Debian 默认）和 GNU 版（`netcat-traditional`），参数略有差异，`-e` 执行命令只有 GNU 版和 nmap 的 `ncat` 支持。

```bash
nc -vz 10.0.0.1 80        # 探测端口通不通
nc -l 9000                # 监听 9000(tcp)
nc 10.0.0.1 9000          # 连过去(tcp)
nc -l 9000 > file         # 收文件，另一端 nc host 9000 < file
nc -u host 53             # UDP
```

临时测 HTTP 也不用装 curl，手写请求塞进去就行：`printf 'GET / HTTP/1.1\r\nHost: example.com\r\n\r\n' | nc example.com 80`。

### nmap
> 官网：https://nmap.org/

端口扫描和主机探测的标准工具，能扫 TCP/UDP 端口、识别服务版本、跑漏洞检测脚本。对非自己的机器扫描前先确认授权，云厂商一般会当成攻击。

```bash
nmap -p 80,443 10.0.0.1              # 扫指定端口
nmap -p- --min-rate 1000 10.0.0.1    # 全端口，加快速度
nmap -sS -Pn -p 1-65535 10.0.0.1     # 半开扫描，要 root，跳过主机存活检测
nmap -sU -p 53,161 10.0.0.1          # UDP
nmap -sV -sC -p 80,443 10.0.0.1      # 探服务版本 + 跑默认脚本
```

网段大、只关心端口开没开时换 masscan 或 zmap，速度是 nmap 的几十倍，但不做服务识别。

## 进程管理

### systemd
> 官方文档：https://systemd.io/

大多数发行版的 init 系统（PID 1），开机启动、服务守护、日志、挂载、定时任务都归它管，cron 的活也被 `.timer` 接走了一部分。

- 单元（unit）：配置文件放在 `/etc/systemd/system/` 或 `/usr/lib/systemd/system/`，常用的几类：
  - `.service`：服务单元，`ExecStart=` 写要跑的程序，`Type=simple` 常驻、`Type=oneshot` 跑完即退
  - `.timer`：定时器单元，到点触发对应的 `.service`，用来替代 cron
  - `.socket`：套接字单元，systemd 先监听端口或 Unix socket，有连接进来才拉起服务，即按需启动
  - `.target`：目标单元，把一组 unit 打包成一个阶段（`multi-user.target`、`graphical.target`），相当于旧式的运行级别
  - 其余还有 `.mount`、`.path`、`.device`、`.slice`，平时碰得少
- 服务操作：`systemctl start|stop|restart|status 名称`，要开机自启再加 `enable`
- 看日志：`journalctl -u 名称 -f`，不用自己重定向到文件
- 定时任务：`.timer` + `.service`，时间写在 `OnCalendar=`，`systemctl list-timers` 查
- 崩溃拉起：unit 里写 `Restart=always`

### crond 定时任务
> 查看格式：`man 5 crontab`

Linux 的定时任务守护进程，Debian/Ubuntu 的包叫 `cron`，RHEL/CentOS 叫 `cronie`。用 `crontab -e` 编辑自己的任务表，一行一条，前面是五个时间字段：

```bash
# 分 时 日 月 周   命令
  0  3  *  *  *   /usr/local/bin/backup.sh
```

`crontab -l` 看当前任务，`systemctl status cron`（或 `crond`）看服务有没有在跑。日志要自己重定向到文件，错过的时间点也不会补跑。
